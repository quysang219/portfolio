Case study · 02 · Operator surface

SEC MGMT — Self-Service Security Platform.

Case 01 fixed the read. This one fixes the write — an in-house web app that lets ~200 system owners and administrators record comments, plans, exceptions and approvals next to the very findings they're looking at, instead of in their inbox.

JavaScript · PostgreSQL · Workflow · RBAC
01 How it started

The interaction gap.

Even after the central report landed, the workflows were still overloading. The bottleneck had moved — from the read side to the interaction around findings.

The dashboard told you exactly where the gap was. It didn't tell you what was happening with it. Did anyone attempt to fix this? Are we waiting for a vendor release? A test date? Is an exception in flight? Was an exemption ever approved, by whom, and when?

Vignette · 01
Vulnerabilities
An unremediated, overdue finding sits on the report with no context. Vendor release pending? Test date scheduled? Exception in draft? The numbers were honest. The story was missing.
Vignette · 02
Firewall Review
After findings and recommendations were sent to system owners, they needed somewhere to log justifications — why this unsafe port is still open, what this rule actually serves. Email threads don't survive a quarter.
Vignette · 03
User Account Review
Sometimes an account needs to be kept — it's actually a service account, not a person. There was no in-platform way to record that decision so the next review wouldn't re-flag it.

Security experts handled all of this on their own agility. Each workflow had a different format of collaboration — emails, Teams chats, Excel sheets. The interaction layer was running on muscle memory.

A finding without context is just a number.
02 How it evolved

The Power BI ceiling.

We tried writeback inside Power BI first. Power BI Report Server is a packaged Microsoft product — self-service cell-level writeback isn't part of its surface.

Third-party writeback visuals exist on the market. We sized them against our population and the math didn't land.

We serve roughly 200 users per quarter: system owners and administrators. That's a small population by license count, but a large one by role. Per-seat custom-visual pricing is built for very different distributions — high volumes of casual readers, not a few hundred deeply-engaged decision-makers. The writeback layer had to step outside the BI tool.

Power BI Report Server · read → Internal web app · write
Small in count, large in role.
03 How it matured

Building in-house.

We developed an in-house web application with simple writeback capabilities, sized for the actual population — a few hundred owners and admins who needed a structured way to talk back to the report.

What surprised us was how repeatable the shape was. No matter which security program we onboarded next, the same three motions appeared, once each per finding.

Write
Owners record comments, plans, queries and exception requests against the actual finding they're looking at — not a copy of it pasted into an email.
Review
Security reviews and approves or responds, in-platform, with the finding still in context. The decision and its rationale stay attached to the data.
Automate
Routine clarifications and stalled-thread follow-ups don't need a human first-touch. The platform handles them, the team handles the cases that need judgment.

That three-step shape became the canonical workflow template. Onboarding a new program is no longer a one-off design exercise; it's a mapping exercise — fit the program to write → review → automate.

The same three motions, once each per finding.
04 What it is now

The SEC MGMT Self-Service Platform.

The operator surface for everything above — three pillars, one writeback layer, every interaction captured next to the data.

Pillar · 01
Workflow engineering
End-to-end onboarded: system owner comments, security review, approval or response. The dashboard's finding now has a thread on it instead of a missing inbox conversation.
Pillar · 02
Workflow automation
SECAI sits behind the platform and replies to system owners — clarifies routine queries, follows up on stalled threads, frees the team for the cases that actually need judgment.
Pillar · 03
Finding depth
Findings stopped appearing blank. Each carries the story behind it — plans, exception requests, queries, notes. The four you'd actually see in production: vendor release, test date, exception requested, service account.
The platform doesn't replace judgment — it moves judgment into the platform.
