Case study · 01 · Executive surface

SEC MGMT Measurement Report — Centralized Security Reporting.

How a quarterly Excel loop for vulnerability remediation became a bank-wide measurement instrument — covering ~30,000 production assets and six security programs — and what it took to get there.

Power BI · DAX · Snapshot model · Editorial design
01 How it started

The Excel loop.

When I first joined IT Security, I was in charge of vulnerability remediation. The work ran on email and spreadsheets.

We scanned a known inventory, exported the results to Excel, split the file per team, password-protected each one per the bank's regulations, and sent them out. Teams fixed what they could, told us by hand, we rescanned, diffed, and started again. Per asset. Per quarter. Per team.

The painful part wasn't the work — it was that the loop didn't know what it was. Circular 09 mandates a quarterly scan-and-fix cycle, and the regulation defines a vulnerability as fixed if it does not reappear in a rescan compared to the start-of-quarter snapshot. Once you name it that way, the workflow isn't a workflow — it's a snapshot diff. It belongs in a data model, not a mailbox.

I worked with my data engineer to land the tables. Power BI Report Server became the surface teams self-served from. They could now see their own latest vulnerabilities and remediation status without waiting for a file.

The painful loop wasn't a workflow problem — it was a measurement problem in disguise.
02 How it evolved

From one program to a central surface.

With the first report live, the data engineer kept integrating. Tenable agents joined first; then SIEM, antivirus, EDR, and an asset inventory that grew to roughly 30,000 production assets — on-prem, cloud (S3, RDS, EC2), network devices, physical infrastructure, staff endpoints, ATM/CDM units, container images.

As the data widened, my role widened with it. I sit at the intersection of data quality, visualization, and guiding system owners through their own program. The dashboard is the meeting point.

Role · 01
Data quality
The unglamorous coordination work that decides whether a number is trustworthy enough to act on.
Role · 02
Central visualization
The Security Management Dashboard — one big surface where any team finds their own assets and their own findings.
Role · 03
Workflow onboarding
Standardizing program after program into the same surface, so each new program inherits the model instead of reinventing it.

In this phase the report stopped being a vulnerability report. It absorbed Card Data Scan, Security Agent Coverage, Configuration Hardening, Privileged User Account Review, and Firewall Review — each with its own owner, its own cadence, and its own definition of "fixed." The unifying piece was the snapshot model underneath.

03 How it matured

The 90%+ problems.

As the programs rolled out, compliance lifted from the low-60s toward 90%+. The headline number was no longer the story. As we approached 100%, a second class of finding surfaced — one that low-coverage reporting could never have seen.

Flapping
Security agents switching between online and offline continuously — healthy at any single point, unhealthy across time.
Ownership churn
Vulnerabilities bouncing between assignees — never long enough with one team to actually be fixed.

These aren't visible on a point-in-time bar chart. They're only visible when the report holds memory. The snapshot model that began as a regulatory accounting trick became the load-bearing piece of the architecture.

Reporting itself industrialized in this phase. The most laborious legs — frontend design, data transforms — moved into a pipeline I run with Claude Code. I keep judgment and review. The report stopped being a coverage tracker and became a measurement instrument: progress over time, stability over time, anomaly against baseline.

At low coverage the work is plumbing. At high coverage the work is measurement.
04 What it is now

The SEC MGMT Measurement Report.

The executive surface for everything above — read by leadership, owned by system owners, measured by four lenses.

Lens · 01
Progress Tracking
Every program has a story over time, not just a number today. Teams see their own line move.
Lens · 02
Anomaly Detection
Flapping agents, churning ownership, and other stability signals get their own views — the kind of finding you only see when you hold memory.
Lens · 03
Achievement Recognition
When a team closes the gap, the report shows it. The number on the wall becomes a fact about who, not just what.
Lens · 04
Executive Reporting
Leadership reads posture, not just coverage. Security work that used to be invisible becomes legible.
Coverage tells you where you are. Measurement tells you whether you're moving — and who's moving.
